Measured, not claimed

Every number below comes from site/data/run_metrics.json, which scripts/run_local.py writes at the end of a real end-to-end run. Re-run it and this page changes.

Latency: source commit → alert

For each alert: the time it was written to Gold minus the source commit time of the newest change behind it. The local run triggers the pipeline once per simulated hour, so this is the pipeline's processing time. On Databricks, add up to one schedule interval (5 minutes in databricks.yml). Either way it replaces a T+1 batch.

Detection quality

The simulator plants fraud and records it as ground truth that never reaches a source system. An alert counts as a true positive when it shares evidence with a planted case of the same rule. The impossible-travel rule's false positives are real cardholders at the start or end of a trip: a last purchase in Lisbon and a first one in Madrid within the hour. A production rule would use distance and minimum travel time per country pair. One planted case can raise two alerts (going out and coming back), which is why true positives can exceed planted cases.
