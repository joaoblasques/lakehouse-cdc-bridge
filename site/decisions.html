Decisions

Architecture decision records

The choices that shaped the project: what was considered, what was picked, and what it costs.

ADR-001 · Capture runs in Databricks notebooks, not Debezium

Context. The textbook setup is Debezium on Kafka Connect, writing to Kafka, with Databricks as a consumer. The target platform does the reverse: Databricks applications monitor the sources and publish events to Confluent.

Decision. Capture is Python adapters run as Databricks notebook tasks, with watermarks and audit in Delta.

Consequences. One platform to operate and one place for lineage and access control (Unity Catalog). It also covers sources Debezium can't, such as an SMB file share. The cost is polling latency (the schedule interval) instead of streaming from the log, and the capture code is ours to maintain.

ADR-002 · At-least-once on the wire, exactly-once in Delta

Decision. No Kafka transactions. The producer is idempotent (enable.idempotence, acks=all), the watermark is committed only after a flush succeeds, event IDs are deterministic, Bronze deduplicates on event_id, and Silver ignores anything not newer than what it already has.

Why. Kafka transactions would not cover the Delta writes anyway. Deterministic IDs make every step safe to retry, which is simpler to reason about and to test.

Cost. A non-Delta consumer must also deduplicate on event_id. That is documented in the event contract.

ADR-003 · File-share CDC with a manifest, not Auto Loader

Auto Loader reads ADLS, Blob storage and Unity Catalog volumes, not Azure Files. A copy step (Azure Files → ADLS) followed by Auto Loader would work, but it adds a hop and a second place where files can go missing. The adapter lists the share directly and keeps (name, etag, sha256) per version, so a re-sent file is detected as an update.

ADR-004 · Soft deletes in Silver

Silver keeps deleted rows with _is_deleted = true. That prevents a late, older insert from bringing a deleted row back, and it keeps evidence for the fraud rules: an expired card authorisation is still an attempt. Consumers that want current state filter on NOT _is_deleted, as reconciliation does.

ADR-005 · JSON events with a published JSON Schema; Schema Registry next

The MVP publishes JSON validated against schemas/change_event.schema.json in tests. The production step is registering it in Confluent Schema Registry with BACKWARD compatibility and serialising through it. The envelope already carries schema_version and an event header.

ADR-006 · Topics are provisioned, not auto-created

Auto-create is disabled. ensure_topics creates missing topics (3 partitions; replication 3 on Confluent Cloud) before Bronze subscribes. An empty table can't make a pipeline fail, and topic naming stays a decision someone made.

ADR-007 · Develop locally, run the cloud demo in short bursts

Databricks Free Edition limits outbound internet until you verify identity. Confluent Cloud's sign-up credit expires after about 30 days. Everything is therefore built and tested against Docker (SQL Server 2022, Confluent cp-kafka) with local Spark and Delta, then deployed with the Asset Bundle for a short cloud run.
