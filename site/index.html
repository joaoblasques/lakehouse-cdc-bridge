The problem

How a typical bank works today

  • Customer and account data sits in several systems: a mainframe, a cards database, a payments database, and files that partner banks drop in a shared folder.
  • Each team that needs the data queries those systems on its own. That is slow, and on a mainframe it costs money every time (MIPS).
  • Fraud checks run overnight (T+1). A card stolen at 10:00 is only noticed the next morning.
  • When a regulator asks where a number came from, it takes days to find out.

What this project does instead

  • Captures every change in each source system as it happens (change data capture), running on Databricks.
  • Publishes each change once to a shared stream (Kafka). Any team can read it without touching the source systems.
  • Keeps a complete, checkable history in Delta Lake, and proves nothing went missing (reconciliation).
  • Flags fraud in seconds, and measures how accurate those alerts are.

Technology, and what each part does

Capture

Small Python programs (source adapters) run as Databricks notebooks. One reads SQL Server's change log, one watches an Azure File Share, one queries DB2.

Transport

Kafka on Confluent: one topic per table, plus a dead-letter queue for records that fail validation.

Storage

Delta Lake tables in three layers: raw events, current records, and fraud alerts, plus an audit trail.

Scheduling

One Databricks Workflows job, defined in an Asset Bundle so the whole setup is deployed with one command.

Processing

Apache Spark reads new events incrementally (Structured Streaming) and runs the fraud rules in SQL.

Alert service

A FastAPI microservice reads new alerts from Kafka and gives analysts a queue to confirm or dismiss them.

Quality

Automated tests and checks on every change (CI), including one against a real SQL Server.

Scope, stated plainly

Three of the four sources are connected: SQL Server, an Azure File Share and DB2. The SingleStore connector comes next (see Decisions). The numbers on this site come from a real run on a laptop-sized setup (Docker), not from a cloud deployment. The same code deploys to Databricks unchanged. All data is synthetic.
