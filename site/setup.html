Setup guide

Install and run the project on your computer

This guide gives the procedure to install the project, run the tests and run the full pipeline on one computer. You do not need a cloud account.

About this guide

This guide uses the principles of ASD-STE100 Simplified Technical English: short sentences, one instruction in each step, and the active voice. Read each step fully before you do it.

Tells you about a risk to your data or to other software on your computer.

CAUTION The SQL Server, Kafka and DB2 container images are for x86-64 processors only. On a Mac with Apple silicon, Docker must emulate x86-64. SQL Server and Kafka can operate with emulation, but they are slower. DB2 can fail to start with emulation.

2 · Install the tools

Install these four tools. If a tool is already on your computer, make sure that its version is correct.

ToolVersionPurposeCommand to examine the version
GitanyCopies the codegit --version
Docker with Compose v2Compose v2Runs SQL Server, Kafka and DB2 (containers)docker compose version
Java (for example Eclipse Temurin)17 or 21Runs Sparkjava -version
uv0.5 or laterInstalls Python and the Python packagesuv --version

NOTE You do not have to install Python. uv installs the correct Python version (3.11 or later) when it is necessary.

  1. Start Docker.
  2. Make sure that Docker operates: 
    docker run --rm hello-world
    Result: The text "Hello from Docker!" shows.

3 · Copy the code to your computer

  1. Open a terminal.
  2. Go to the folder where you keep your projects.
  3. Copy the repository: 
    git clone https://github.com/joaoblasques/lakehouse-cdc-bridge.git
  4. Go to the project folder: 
    cd lakehouse-cdc-bridge
    Result: The folder contains the files README.md, docker-compose.yml and pyproject.toml.

NOTE Do all the subsequent commands in this project folder.

4 · Install the Python packages

  1. Install the packages: 
    uv sync --all-extras
    Result: uv shows "Installed" and the number of packages. A .venv folder shows in the project folder.

NOTE The first installation can take some minutes. uv puts all packages in .venv. It does not change the other Python installations on your computer.

5 · Start the services

This procedure starts two services in Docker: SQL Server (the bank's cards database) and Kafka (the event stream).

CAUTION Make sure that no other program uses port 1433 or 9092. If another SQL Server or Kafka uses these ports, stop it first. If you do not stop it, the services in this project do not start.

  1. Start the services: 
    docker compose up -d --wait
  2. Wait until the command stops. The first start downloads approximately 3.7 GB and can take 10 minutes.
  3. Make sure that the two services operate: 
    docker compose ps
    Result: The list shows sqlserver with the status "healthy" and kafka with the status "Up".

6 · Run the tests

  1. Run the main tests: 
    uv run pytest
    Result: The last line shows "passed" and no "failed". This takes approximately 2 minutes.
  2. Run the test that uses the real SQL Server: 
    uv run pytest -m integration
    Result: The last line shows "1 passed".

NOTE The first Spark test downloads two Java libraries (Delta Lake and the Kafka connector). This is necessary one time only.

7 · Start DB2 (optional)

DB2 plays the bank's mainframe. The pipeline operates without DB2. If you do not start DB2, the pipeline uses only SQL Server and the partner files, and it tells you this.

CAUTION The DB2 image is 4.3 GB. DB2 also operates in privileged mode, which gives the container full access to your computer. Start DB2 only on a computer that you use for development.

  1. Start DB2: 
    docker compose --profile db2 up -d db2
  2. Wait until DB2 is ready. This can take 5 to 10 minutes. To see the progress, use this command: 
    docker compose logs -f db2
    Result: The text "Setup has completed." shows.
  3. Push Ctrl + C to stop the log display. DB2 continues to operate.
  4. Run the test that uses the real DB2: 
    uv run pytest -m db2
    Result: The last line shows "1 passed".

8 · Run the full pipeline

The pipeline creates bank data, captures each change, sends the changes through Kafka, keeps them in Delta Lake tables and finds fraud. It writes the results to site/data/run_metrics.json.

CAUTION The --fresh option deletes and starts again the SQL Server and Kafka containers. It also deletes the .local folder and all rows in the DB2 loans table. Do not use it if you want to keep data from an earlier run.

  1. Run the pipeline: 
    uv run python scripts/run_local.py --fresh
  2. Wait until the command stops. This takes approximately 5 to 15 minutes. The time changes with the speed of your computer. Result: The terminal shows one line for each round, from "round 0" to "round 6". At the end, it shows a summary of the alerts and the latency.

NOTE To change the size of the run, use these options: --rounds (the number of simulated hours, default 6) and --customers (default 150).

9 · See the results

  1. Start a small web server for the website: 
    python -m http.server -d site 8000
  2. Open http://localhost:8000 in your web browser. Result: The website shows the results of your run. The date on the Results page is the date of your run.
  3. Push Ctrl + C in the terminal to stop the web server.

10 · Stop and remove the services

  1. To stop the services and keep their data, use this command: 
    docker compose --profile db2 stop
  2. To remove the services and their data, use this command: 
    docker compose --profile db2 down -v
  3. To remove the local Delta tables, delete the .local folder: 
    rm -rf .local

NOTE The container images stay on your computer. To remove them and recover the disk space, use docker image rm with the image names in docker-compose.yml.

11 · Troubleshooting

ProblemPossible causeAction
docker compose up shows "port is already allocated"Another program uses port 1433, 9092 or 50000Stop the other program. Then do step 5 again.
The sqlserver service does not become "healthy"Docker does not have sufficient memoryGive Docker a minimum of 8 GB of memory in its settings. Then do step 5 again.
Tests show "JAVA_GATEWAY_EXITED"Java is not installed, or its version is not 17 or 21Install Java 17 or 21. Make sure that java -version shows the correct version.
Tests stop at "Ivy" or "resolving dependencies"Spark cannot download its Java librariesMake sure that the internet connection operates. Then run the tests again.
The pipeline shows "DB2 not reachable"DB2 is not started or is not readyThis is not an error: the pipeline continues without DB2. To use DB2, do step 7.
The pipeline shows "Failed to acquire idempotence PID" one timeKafka is not fully ready yetNo action is necessary. The pipeline tries again automatically.
The pipeline stops with "ReconciliationError"The data in Delta does not agree with the source dataRun the pipeline again with --fresh. If the error stays, send the full error text in a GitHub issue.
